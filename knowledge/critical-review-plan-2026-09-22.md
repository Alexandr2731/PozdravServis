## Часть 2. Критический разбор проекта (по факту кода и переменных окружения)

### P0 — блокирует запуск / деньги

**1. Оплаты нет вообще.**
И `greeting.js`, и `song.js` сразу генерируют готовый результат и отдают его клиенту — бесплатно, без каких-либо ограничений. Бот в текущем виде — это бесплатная раздача платных генераций HeyGen/Mureka всем желающим. Это не соответствует ни одному из зафиксированных решений (оплата → 2 варианта → retry → возврат баллами).
- Причина: `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` не заданы.
- Дедлайн: Александр даёт ключи ЮKassa — **24.09.2026**. Код оплаты — **29.09.2026**.

**2. Обещанная механика "2 варианта + retry + возврат 50% баллами" не реализована.**
В коде — одна попытка, один вариант, сразу отдаётся финальный файл (даже без превью/водяного знака, о котором договорились 12.09, чтобы закрыть дыру "скачал — просит возврат").
- Дедлайн: реализовать вместе с оплатой — **29.09.2026** (Услуга 1), **06.10.2026** (Услуга 2).

**3. Баллы/баланс невозможны — нет БД.**
`SUPABASE_URL/KEY` не заданы. Без БД нельзя хранить баланс баллов клиента для возвратов.
- Дедлайн: Александр создаёт проект Supabase и даёт ключи — **24.09.2026**. Интеграция — **02.10.2026**.

**4. OPENAI_API_KEY не задан.**
Блокирует сразу три обещанные в приветствии бота фичи: автогенерацию текста поздравления ("помоги написать"), распознавание голосовых на шаге текста, мультяшную стилизацию фото. Пользователь в боте видит кнопку "🤖 Помоги написать" — она упадёт с ошибкой.
- Дедлайн: Александр добавляет ключ — **24.09.2026**.

**5. Юр. часть не закрыта.**
Оферта — черновик (`oferta-draft-2026-09-12.md`), юристом не проверена. Статус регистрации оператором ПДн в РКН — неизвестен (12.09 Александр сказал "сделаю сам", подтверждения с тех пор не было).
- Дедлайн: уточнить статус РКН — сразу, при следующем разговоре. Юр.консультация по оферте — **10.10.2026** (до приёма первых реальных денег).

**6. Бренд рассинхронизирован.**
Новое имя — PozdravServis, но живой бот всё ещё `@TITAL_NAPAMYAT_bot`, репо и Railway-сервис — `na-pamyat-d`. Решение по юзернейму бота нужно ДО начала любых маркетинговых материалов.
- Дедлайн: решение — **24.09.2026** (см. Часть 1).

### P1 — мешает росту, не блокирует технический MVP

**7. Сайт (второй канал) не начат.**
README утверждает "Telegram-бот и сайт работают поверх одного общего бэкенда" — по факту в репозитории нет ни одного файла сайта. Формулировка в README вводит в заблуждение о реальном статусе.
- Рекомендация: явно отложить сайт до после запуска бота, зафиксировать в README как "план", а не текущее состояние.

**8. Мультяшный стиль — заглушка.**
"Мультяшный стиль пока в разработке — сделаем в обычном" — хардкод в `greeting.js:102`. Зависит от OPENAI_API_KEY (п.4) и не проверен технически (неизвестно, анимирует ли HeyGen нефотореалистичные изображения).
- Дедлайн: реализация и тест — **13.10.2026** (после появления ключа).

**9. Услуга 2 без "сохранить мелодию, поменять текст".**
Договорённость от 12.09 (`reviseLyrics` в Mureka API) не реализована в `src/services/mureka.js` — только полная генерация с нуля.
- Дедлайн: **06.10.2026**, вместе с оплатой Услуги 2.

**10. Цена нигде не показывается клиенту.**
Ни в приветствии, ни перед генерацией бот не называет стоимость — пользователь узнаёт цену только на этапе оплаты (когда она появится). Сейчас это не проверяемо, т.к. оплаты нет.
- Дедлайн: добавить показ цены — **29.09.2026**, вместе с шагом оплаты.

**11. Доставка результата по прямой ссылке (URL).**
`ctx.replyWithVideo(videoUrl, ...)` и аналогично для аудио — Telegram сам скачивает файл по URL от HeyGen/Mureka. Не проверено на реальных больших файлах / случае истёкшей ссылки (обе платформы могут держать файл ограниченное время).
- Дедлайн: тест на реальном заказе — **17.10.2026** (в рамках тестового прогона полного флоу).

**12. Нет тестов, минимум логирования.**
Кроме одного `console.error` в `bot.js` (`setWebhook failed`) — никакого логирования ошибок генерации, нет автотестов. При реальных клиентах диагностика сбоев будет вслепую.
- Дедлайн: базовое логирование ошибок — **06.10.2026**. Автотесты — не критично для MVP, отложить.

**13. `.railway-trigger`.**
Файл-костыль для форсирования редеплоя (воркэраунд бага Railway с `variableUpsert`, найден 14.09). Работает, но это хрупкая точка инфраструктуры — держать в уме, не трогать без необходимости.
