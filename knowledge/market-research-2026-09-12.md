## Критическая находка: у Suno НЕТ официального публичного API
Партнёрский трек анонсирован летом 2026, но легально подключить Suno к своему продукту, ориентированному на РФ, по прежнему нельзя. Это значит:
- Бро.Хит и Sonata почти наверняка используют неофициальные/серый обёртки над Suno-аккаунтами (риск бана аккаунта, нестабильность)
- **Альтернативы с официальным легальным API:** Soundful (от $10/мес, безлимит, но упор на фоновую музыку без вокала), ElevenLabs Music (снизили цены на API на 50% в мае 2026, поддерживает вокал) — стоит протестировать как основу вместо серого Suno-врэппера
- Для видео/аватар-части (Услуга 1) с легальным API всё в порядке — HeyGen, D-ID, Synthesia официально продают коммерческий доступ для клонирования/анимации лица

## Юридические риски (РФ, 2026)
1. **Дипфейки:** сейчас законодательно запрещены только в предвыборной агитации (ФЗ №130 от 02.05.2026). Более широкий законопроект (сенатор Кожин) о запрете создания дипфейков БЕЗ СОГЛАСИЯ человека ещё не принят, но движется — штрафы 9-30 тыс.₽ адм., до 7 лет за тяжкие случаи (провокации, представители власти). Наш кейс: клиент грузит СВОЁ фото/голос — риска нет. Риск возникает, если клиент грузит фото/голос ТРЕТЬЕГО ЛИЦА (например, "поздравление от бабушки", а бабушка фото не давала) — здесь нужен чек-бокс согласия/гарантии клиента, что у него есть право использовать это изображение.
2. **Персональные данные:** фото и особенно голос — потенциально биометрические персональные данные (спорный момент, если используются для идентификации — тут нужна консультация юриста по конкретному кейсу). Как ИП/самозанятый вы становитесь оператором ПДн при систематической обработке — нужно уведомление в Роскомнадзор, форма согласия (ФИО оператора, цель обработки, состав данных, срок хранения, право отзыва).
3. **Авторское право на результат:** контент, созданный ИИ без творческого участия человека, по действующей практике РФ не охраняется авторским правом (нет автора-человека) — то есть нельзя обещать клиенту "эксклюзивные авторские права" в строгом смысле. Для персонального подарка это не критично, но стоит отразить в оферте формулировкой в духе "результат передаётся как есть, без гарантии исключительных прав".
4. **Форма бизнеса:** самозанятость (НПД) подходит для старта (лимит дохода ~2.4 млн₽/год, нельзя нанимать сотрудников) — оптимально для MVP. При росте/найме — переход на ИП с УСН 6%.

## Уточнение по возврату/переделке (2026-09-12)
Александр согласен: исключить возможность скачивания результата, пока клиент явно не подтвердит "меня всё устраивает". Технически это значит:
- Варианты (А/Б, потом В при переделке) показываются как ПРЕВЬЮ (не финальный файл для скачивания) — например, водяной знак/сжатое качество/просмотр только в боте
- Финальный файл без ограничений открывается только после явного подтверждения выбора клиентом ("беру этот вариант")
- Это автоматически закрывает дыру "скачал и просит возврат", раз скачивание = подтверждение.
Экономику (себестоимость 3 генераций на заказ) Александр уже считал сам — не пересчитываем.
Вопрос возврата остаётся открытым, Александр обещал ещё подумать.

## Фишка: свободный ввод "в стиле артиста X" вместо ограниченного списка жанров (2026-09-12)
Александр заметил: конкуренты дают только фиксированный список жанров (поп/рок/классика/рэп/шансон/диско90х/свой вариант — неясно какой). Предложил разрешить указывать конкретного исполнителя как референс (например "в стиле Билана" или "Стаса Михайлова").

Юридический разбор (важно для реализации):
1. Музыкальный СТИЛЬ (жанр, манера, темп) — не объект авторского права, использовать можно свободно.
2. КОПИРОВАНИЕ конкретного произведения (переработка) — нарушение по ст. 1266 ГК РФ, нужно согласие правообладателя. Не проблема, если генерация действительно оригинальна, а не имитация конкретной песни.
3. ПУБЛИЧНОЕ заявление "песня в стиле [известный артист]" в маркетинге — отдельный риск по праву на имя живого человека (ст. 152.1 ГК РФ) и законодательству о рекламе — может выглядеть как неавторизованное использование имени/репутации артиста, намёк на его причастность к продукту.

Рекомендация агента (принять решение с Александром): 
- Клиенту разрешить свободный ввод референса артиста в описании заказа (это его слова, не наша реклама)
- Внутри системы этот запрос транслируется (через LLM) в нейтральный технический промпт для Mureka — описательными характеристиками (тип вокала, жанр, манера), БЕЗ имени артиста в самом запросе к движку
- Никогда не маркировать готовый результат публично как "в стиле [артист]" — избегаем ассоциации с конкретной звездой в открытую
Статус: предложение, ждём подтверждения Александра.

## Решение подтверждено (2026-09-12)
Александр подтвердил: закрепляем возможность заказать песню "в стиле" известного исполнителя по схеме, предложенной агентом — свободный ввод референса от клиента, внутренняя трансляция в нейтральный промпт для Mureka (без имени артиста), без публичной маркировки результата именем артиста. Статус: РЕШЕНО, включено в продуктовые требования.
