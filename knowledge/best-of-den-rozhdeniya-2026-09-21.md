## Идея: воронка вместо независимых услуг (стоит рассмотреть)

Сейчас у нас клиент выбирает Услугу 1 или Услугу 2 в начале. В den-rozhdeniya другая модель — **один заказ = последовательная воронка** с апселлами: Текст → (апселл) Песня → (апселл) Клип, каждый этап можно купить отдельно и вернуться позже. Плюс: не нужно решать всё сразу, чек растёт естественно. Минус: сложнее в реализации (нужен state per этап, а не одна сцена). Не переделывать прямо сейчас, но держать в уме при следующем витке архитектуры бота.

## Расширение поводов за пределы дня рождения

В den-rozhdeniya отдельно решили не ограничиваться днём рождения: 23 февраля, 8 марта, 14 февраля, Новый год, День матери/учителя, 1 сентября, свадьбы/годовщины — те же самые даты у всех клиентов одновременно, что даёт концентрированные рекламные пики вместо размазанного потока по случайным ДР. У нас `occasions.js` уже параметризован — технически расширить дёшево, стоит сделать при выходе на маркетинг.

## Клип — двухуровневая стратегия (найдено 05.09.2026 в том проекте)

1. **Базовый клип** — НЕ генеративное видео, а шаблонное слайд-шоу (фото + субтитры текста песни + песня как саундтрек) через Placid/Bannerbear video API — копейки, предсказуемые правки ("замени фото на слайде 3").
2. **Премиум-клип** — lip-sync сервисы (VisionStory, AISong, Zoice) — дороже, но именно "оживление" фото.

У нас пока только один сценарий (стилизация через OpenAI images + HeyGen). Стоит рассмотреть базовый вариант как дешёвую версию для клиентов, которым не нужен премиум.

**Zoice** — доп. кандидат для мультяшного клипа, не рассматривали: dev-API, тариф от $7.99/мес, есть готовая фича "AI Avatar Videos" (фото + аудио → видео до 4K).

## Karaoke — подтверждённая техническая находка

Mureka уже отдаёт **таймкоды по словам** (`lyrics_sections`) прямо в ответе на генерацию песни — отдельный Whisper-этап для караоке-подсветки текста НЕ нужен. Пригодится, когда будем делать фичу "Персональное караоке" (уже в наших планах).

## Точечная правка текста песни — уточнён API-путь

У нас уже была идея "поправить текст, оставив мелодию" (см. market-research). В den-rozhdeniya нашли конкретный путь: Mureka API умеет `reviseLyrics` — обновить текст готовой песни с сохранением мелодии/вокала, без пересборки трека. Проверить при получении доступа к Mureka API, добавить в `src/services/mureka.js` как `reviseLyrics()`.

## Надёжность — уже перенесено в код (2026-09-21)

В den-rozhdeniya был реальный инцидент: обычный `fetch` без тайм-аута зависал навсегда при обрыве соединения (ни резолвится, ни реджектится). У нас был тот же риск во всех трёх сервисах (`heygen.js`, `mureka.js`, `openai.js` — везде голый `fetch`). Сделано:
- Добавлен `src/utils/fetchWithTimeout.js` (20с по умолчанию, 60с для генерации картинки).
- Все вызовы в `heygen.js`, `mureka.js`, `openai.js` переведены на него.
- `waitForSong` в `mureka.js` теперь переживает одиночный сетевой сбой при опросе статуса и продолжает опрашивать тот же `taskId`, а не считает это провалом генерации (та же находка — у Mureka API соединение при опросе действительно иногда рвётся).

## Что НЕ переносим и почему

- **TypeScript/state machine/оркестратор целиком** — не переписываем стек, риск сломать рабочий деплой не оправдан на этой стадии; идею состояний по этапам держим в уме на будущее (см. "воронка" выше).
